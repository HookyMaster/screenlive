## ScreenLive 录屏软件

完成从零开发一个鼠标自动追踪的 9:16 竖屏录屏工具（Python + FFmpeg）。

### 关键决策
- **捕获**: mss 按 9:16 region 直接截取小窗口（横屏 1080p→608×1080，4K→1214×2160），不截全屏 → CPU 占用大幅降低
- **编码**: 原始 BGRA 帧直接管道喂 FFmpeg stdin，无中间文件；自动探测 NVENC/QSV/AMF 硬件编码器，**实测验证**后采用（避免被 ffmpeg -encoders 列表误导）
- **架构**: 捕获线程（按帧率定时）+ 编码线程（流水线写入）+ 有界队列丢帧
- **鼠标追踪**: EMA 平滑目标窗口位置，避免抖动；光标在视频中画出，位置 = 真实鼠标位置（不是窗口中心）
- **DPI**: set_dpi_aware(Per-Monitor) 保证 GetCursorPos 与 mss 物理坐标一致

### 踩坑（已修复）
1. **CursorRenderer** `roi += cursor[..., :3]` 触发 uint8+=float32 casting 错误 → 改为 np.add(..., casting="unsafe") + 限定前3通道
2. **4K 屏** 9/16×2160=1215（奇数）yuv420p 编码失败 → tracker 强制 `win_w &= ~1` 对齐偶数
3. **NVENC 误判** 无 NVIDIA GPU 但 ffmpeg 列表里有 nvenc → 加 verify_encoder() 实测
4. **main.py --duration** 模式没自动开始 → 启动前 toggle()
5. **pynput 失败** 整代码包了 try/except 静默降级

### 性能验证（实测）
- 4K 屏 1214×2160 @24fps，3 秒录制：捕获 58 帧、编码 58 帧、0 丢帧，1.0 MB 输出
- 编码器实测：NVENC/QSV/AMF 均 CUDA_ERROR_NO_DEVICE → 自动回退 libx264 ultrafast
- 抽帧验证：画面是浏览器页面竖屏裁剪 + 鼠标箭头清晰可见
