  - `SetProcessDpiAwareness(2)` 保留(为 mss 坐标)
  - `__init__` 末尾用 `root.after(150, _force_size)` 通过 ctypes `SetWindowPos` 强制设物理像素
  - 目标 1228x972 物理(屏幕 32%×45%), 每 2 秒重复强制防 Tk 缩回
- 调试日志写到 `~/Videos/ScreenLive/gui_debug.log`

## 预览窗口严格等比拖拽(WM_SIZING 子类化)
- 需求: 预览窗口拖拽边缘/角时**全程**保持输出比例, 不能靠事后回弹(原 Configure 回弹有抖动)
- 方案: ctypes 子类化预览窗口 hwnd — `SetWindowLongPtrW(GWLP_WNDPROC)` 替换窗口过程, 拦截 `WM_SIZING(0x214)`:
  - `WM_ENTERSIZEMOVE` 记录起始装饰尺寸(窗口-客户区差值)
  - `_fix_sizing_rect`: 按拖拽边/角确定主维度(左右边以宽为准/上下边以高为准/角以变化量大者为准), 重算另一维使**客户区**严格等于输出比例, 锚定不动的边(拖角固定对角, 拖边固定对边另一维居中)
  - 返回 1 阻止默认处理; 其余消息转发原 wndproc
- 关键坑: ① ctypes 回调对象必须挂 `self` 引用防 GC(否则崩溃); ② 窗口重建(关闭预览再开)时要重新装钩子; ③ 关闭时 `SetWindowLongPtrW` 还原旧 wndproc
- 验证: 8 方向拖拽模拟单测全过(比例误差 <0.001, 锚定边不动), 16:9 比例也验证
- 文件: gui.py 新增 `_install_sizing_hook/_preview_wndproc/_fix_sizing_rect`, `_on_close` 卸载钩子

## 等比拖拽钩子致命崩溃修复(用户报告"自动退出了")
- 现象: GUI 运行约 22s(用户拖预览窗口)后静默退出
- 崩溃栈: `Fatal Python error: PyEval_RestoreThread: GIL released` @ `_preview_wndproc`(3 层递归)
- **根因**: `WM_ENTERSIZEMOVE` 处理中调用了 `canvas.winfo_width()` —— 在 ctypes 窗口过程回调里调用 Tkinter API 会进入 Tcl 层释放 GIL, 嵌套消息递归进回调 → GIL 状态错乱致命崩溃
- 修复: 回调内一律用纯 Win32 API(`GetWindowRect`/`GetClientRect` 取装饰/客户区尺寸), 并加 `_in_wndproc` 递归保护标志(finally 复位)
- 验证: 对真实运行中的 GUI 窗口 `SendMessageW` 发 WM_ENTERSIZEMOVE + 15×WM_SIZING 不再崩溃
- **教训(已写入 win32-aspect-ratio-resize 技能)**: Win32 窗口过程回调里禁止调用任何 Tk/Tcl API, 这是比回调 GC 更隐蔽的坑; 技能示例脚本同步修正

## 修复: 隐藏再显示预览后录制出现黑框(WDA 排除面失效)
